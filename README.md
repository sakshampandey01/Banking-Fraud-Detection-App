# Bank Fraud Detection

A FastAPI + PostgreSQL + React application that scores bank transactions with your saved XGBoost model
(`best_fraud_model_tuned.pkl`), stores them, and shows the results on a dashboard.

```
Analysis.ipynb          training notebook (unchanged)
app/                    FastAPI backend  (app/ml = feature engineering + model loading)
sql/                    database schema, reference data, stored procedure, views
scripts/
  export_preprocessing.py   recompute models/preprocessing.json from the FULL Fraud.csv   <-- run once
  init_db.py                create + initialise the PostgreSQL database
models/preprocessing.json   p99 threshold, type encoding, scaler values (generated by the script above)
frontend/               React + Vite + Tailwind dashboard
tests/                  Python + SQL tests         frontend/tests/  JavaScript tests
backup_original/        the files from your original ZIP that were replaced
docs/REPORT.md          what changed, discrepancies found, exactly which tests passed / could not run
```

> **Before anything works you must run `scripts/export_preprocessing.py` once** (step 6). Your original
> `preprocessing.json` held placeholders (`p99_amount: 0`, empty `type_encoding`, scaler `0/1`). Those numbers can
> only be computed from the full dataset, which was not in the upload. Until the script has run, the API starts but
> **refuses to score** and tells you why (it never guesses).

## Run it on your Mac (copy-paste, in order)

Open **Terminal**. If a command says `command not found: brew`, install Homebrew first from https://brew.sh.

### 1. Put the repaired files into your project folder

Your folder is `~/Desktop/Bank-Fraud-Detection/` and already contains `Fraud.csv` and
`best_fraud_model_tuned.pkl`. The ZIP contains neither, so unzipping over the folder keeps them.

```bash
# safety copy first (about the size of your dataset)
cp -R ~/Desktop/Bank-Fraud-Detection ~/Desktop/Bank-Fraud-Detection.backup

# unzip the repaired project on top (adjust the path if the ZIP is somewhere else)
unzip -o ~/Downloads/Bank-Fraud-Detection-repaired.zip -d ~/Desktop/

cd ~/Desktop/Bank-Fraud-Detection
ls            # you should see Fraud.csv, app, sql, scripts, frontend, ...
```

The model file may stay in the project folder **or** be moved to `models/`; the app finds it in either place.

### 2. Install the tools (once)

```bash
brew install python@3.12 postgresql@16 node libomp
brew services start postgresql@16
```

* Python **3.10 or newer** is required (macOS's built-in Python 3.9 is too old).
* `libomp` is needed by XGBoost on macOS.
* Homebrew's PostgreSQL uses your macOS username and no password, which is what `.env.example` assumes.

### 3. Python environment

```bash
cd ~/Desktop/Bank-Fraud-Detection
python3.12 -m venv venv
source venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

**Version warning:** your model was pickled by a particular XGBoost/scikit-learn version. Where you trained it
(your notebook environment) run `pip show xgboost scikit-learn`, and if the versions differ from what pip just
installed, install those exact ones: `pip install xgboost==X.Y.Z scikit-learn==A.B.C`.

### 4. Configuration

```bash
cp .env.example .env
```

The defaults work with Homebrew PostgreSQL. Only edit `.env` if your database needs a user/password.

### 5. Create the database

```bash
python scripts/init_db.py --demo
```

This creates the `fraud_db` database if needed, builds the tables, seeds the five transaction types
(`CASH_IN=0, CASH_OUT=1, DEBIT=2, PAYMENT=3, TRANSFER=4`, the notebook's LabelEncoder order) and adds six
made-up demo accounts (`C900000001`…`C900000004`, `M900000001`, `M900000002`) so you can try the form. It is safe to
run again. (`--reset --yes` wipes everything.)

### 6. Generate the real preprocessing values from the full dataset  ← the important step

```bash
python scripts/export_preprocessing.py
```

It reads `~/Desktop/Bank-Fraud-Detection/Fraud.csv` (6.36 M rows; roughly 1.2 GB of RAM and about 10–60 seconds),
replays the notebook exactly, and writes `models/preprocessing.json`. You will see progress lines like:

```
OK      rows: 6,362,620 (notebook: 6,362,620)
OK      fraud rows: 8,213 (notebook: 8,213)
p99_amount = ...
OK      rows above p99: 63,627 (notebook: 63,627)
OK      test rows: 1,272,524 ...
```

Every `OK` means your file matches the notebook's printed numbers. If the model file is present the script also scores
the test split and compares with notebook cell 38 (`TP 1474 / FN 169 / FP 3612 / TN 1,267,269`). It ends with
`RESULT: identical to notebook cell 38`, or tells you plainly if something differs. **If you see `DIFFERS`, stop and
read `docs/REPORT.md` section "If the script reports a difference".** Use `--csv /other/path/Fraud.csv` if the file is elsewhere.

### 7. Start the backend

```bash
uvicorn app.main:app --reload
```

* API docs: http://localhost:8000/docs
* Health: http://localhost:8000/api/health → should show `"status": "ok"` and `"ready_for_scoring": true`.
  If not, `issues` says exactly what is missing (model file, preprocessing, database).

### 8. Start the frontend (second Terminal window/tab)

```bash
cd ~/Desktop/Bank-Fraud-Detection/frontend
npm install
cp .env.example .env.local
npm run dev
```

Open http://localhost:5173. Then:

1. In **Check a transaction → Score & save**, choose `TRANSFER`, amount `5000`, from `C900000001`, to `C900000002`, and press **Score and save**.
2. You get the probability, risk level (LOW / MEDIUM / HIGH) and the decision threshold; the transaction appears in the
   table, the counters update, and a HIGH result blocks the transaction and the sending account (audited).
3. **Check only** scores typed-in balances without saving anything.

### Stopping / restarting

`Ctrl+C` in each Terminal window. Next time just: `cd ~/Desktop/Bank-Fraud-Detection && source venv/bin/activate && uvicorn app.main:app --reload`, and `npm run dev` in `frontend/`. If PostgreSQL is not running: `brew services start postgresql@16`.

## How a prediction works

```
form → POST /api/transactions/evaluate
        1. look up both accounts and their balances (database)
        2. build the 9 features, scale them like the notebook's RobustScaler → your XGBoost model
        3. CALL sp_process_transaction: one atomic database transaction
             probability ≥ model threshold (0.908351…)  → HIGH   → transaction BLOCKED, no money moves, origin account BLOCKED
             probability ≥ MEDIUM_RISK_THRESHOLD (0.5)  → MEDIUM → approved and flagged
             otherwise                                  → LOW    → approved
```

Features (verified against the notebook, in the model's column order): `step`, `amount`, `log_amount = log1p(amount)`,
`is_high_amount = amount > 99th percentile`, `hour = step % 24`, `is_night = hour in {0–5, 22, 23}`,
`balance_diff_orig = oldbalanceOrg − newbalanceOrig`, `balance_diff_dest = newbalanceDest − oldbalanceDest`,
`type_enc` (alphabetical LabelEncoder); all nine then scaled with a RobustScaler fitted on the 80 % training split.

### API

| Method & path | Purpose |
|---|---|
| `GET /api/health` | readiness: model, preprocessing, database, and what is missing |
| `POST /api/transactions/evaluate` | score **and store** (`type, amount, orig_account, dest_account, step?`) |
| `POST /api/predict` | score only, you supply the four balances (nothing stored) |
| `POST /api/predict/batch` | up to 1000 of the above in one call |
| `GET /api/transactions` | history; filters `source, status, risk_level, account, limit, offset` |
| `GET /api/transactions/{id}` · `/{account}` | one transaction · everything an account sent/received |
| `GET /api/stats` · `/api/stats/summary` | dashboard numbers |
| `GET/POST /api/accounts`, `GET /api/accounts/{n}`, `PATCH …/status`, `GET …/audit` | accounts, analyst unblock, audit trail |

Errors always look like `{"error": {"code": "INSUFFICIENT_FUNDS", "message": "…"}}`; a not-ready model/database gives HTTP 503 with instructions.

## Tests

```bash
source venv/bin/activate
pip install -r requirements-dev.txt

python -m pytest                                  # unit tests (model/feature/preprocessing/script)

createdb fraud_test                               # throw-away database for the DB + API tests
export TEST_DATABASE_URL=postgresql+psycopg://localhost:5432/fraud_test
python -m pytest -v                               # now also runs SQL, concurrency and HTTP API tests

cd frontend && npm test                           # JavaScript tests (no browser needed)
```

Some tests **skip** (they do not fail) when something is missing: `test_real_artifact.py` needs your real model and the
generated `preprocessing.json`; `test_api.py` and `test_sql.py` need `TEST_DATABASE_URL`. After step 6 they all run.
Tests that use synthetic data say so in their docstrings. See `docs/REPORT.md` for which ones were actually executed.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Health says `PREPROCESSING_NOT_READY` | run step 6 |
| `MODEL_UNAVAILABLE: Model file not found` | put `best_fraud_model_tuned.pkl` in the project folder or `models/` |
| `Could not load … missing package xgboost` / version errors | step 3, install the same xgboost/scikit-learn versions as the notebook |
| `DB_UNAVAILABLE` | `brew services start postgresql@16`; check `DATABASE_URL` in `.env` |
| `DB_SCHEMA_MISSING` | run step 5 |
| `DB_ENCODING_MISMATCH` | `python scripts/init_db.py` re-seeds the types |
| Dashboard says "Couldn't load data" | backend not running, or `VITE_API_URL` in `frontend/.env.local` is wrong |
| `ModuleNotFoundError` | `source venv/bin/activate` in this Terminal window |
| `psql`/`createdb` not found | `brew link postgresql@16` or add `/opt/homebrew/opt/postgresql@16/bin` to your PATH |
